# Fiat Rate API Architecture

**Date**: October 12, 2025  
**Status**: ✅ Documented

---

## 📊 Architecture Overview

### Why GraphQL Instead of Direct API Calls?

The frontend **does not** call the external fiat rate service directly. Instead, it uses a **GraphQL proxy pattern** through the backend API. Here's why:

---

## 🏗️ Current Architecture

```
┌─────────────────┐
│   Frontend      │
│   (Next.js)     │
└────────┬────────┘
         │

┌─────────────────┐

         │
         ▼
┌─────────────────┐

```

## 🔍 Why This Architecture?

### 1. **Security & API Key Management** 🔐
- External API credentials stay on the backend
- Frontend never exposes sensitive API keys
- Backend can add authentication layers

### 2. **CORS Prevention** 🌐
- No cross-origin issues
- All frontend requests go to same domain (`/graphql`)
- Backend handles external API CORS

### 3. **Data Transformation** 🔄
- Backend normalizes different API versions
- GraphQL schema provides consistent interface
- Frontend doesn't need to handle API changes

### 4. **Caching & Performance** ⚡
- Backend can implement caching strategies
- GraphQL layer provides query optimization
- Reduce external API calls

### 5. **Rate Limiting Protection** 🛡️
- Backend controls request frequency
- Protects against external API rate limits
- Can implement request batching

### 6. **Centralized Error Handling** 🚨
- Backend catches external API failures
- Returns consistent GraphQL errors
- Frontend gets predictable error format

### 7. **Multiple Data Sources** 📊
- Backend can aggregate multiple APIs
- Single GraphQL query for complex data
- Hide complexity from frontend

### 8. **Monitoring & Logging** 📈
- Backend logs all external API calls
- Track API usage and performance
- Debug issues from backend logs

## 📝 Data Flow Example

### Step 1: Frontend Query
```typescript
// Frontend component
const { data } = useGetAllFiatRateQuery();
```

### Step 2: GraphQL Request
```http
POST /graphql HTTP/1.1
Content-Type: application/json

{
  "query": "query GetAllFiatRate { getAllFiatRate { currency fiatRates { coin ts rate } } }"
}
```

### Step 3: Backend Resolver
```typescript
// Backend fetches from external API
const response = await httpService.get('https://aws-dev.abcpay.cash/bws/api/v3/fiatrates/');
```

### Step 4: External API Response
```json
{
  "btc": [
    { "ts": 1697123456789, "code": "USD", "name": "US Dollar" },
    { "ts": 1697123456789, "code": "EUR", "name": "Euro" }
  ],
  "xec": [...]
}
```

### Step 5: Backend Transformation
```typescript
// Transform to GraphQL schema format
return {
  currency: "BTC",
  fiatRates: [
    { coin: "USD", ts: 1697123456789, rate: 0 },
    { coin: "EUR", ts: 1697123456789, rate: 0 }
  ]
}
```

### Step 6: Frontend Receives
```typescript
data.getAllFiatRate = [
  {
    currency: "BTC",
    fiatRates: [
      { coin: "USD", ts: 1697123456789, rate: 0 },
      { coin: "EUR", ts: 1697123456789, rate: 0 }
    ]
  },
  ...
]
```

## ⚠️ Current Limitation

**Note**: The v3 fiat rates API returns currency codes and names but **not actual exchange rates**:

```typescript
// v3 API returns:
{ ts: 1697123456789, code: "USD", name: "US Dollar" }

// But GraphQL expects:
{ coin: "USD", ts: 1697123456789, rate: 0.00002345 }
```

**Workaround**: Currently mapping `rate: 0` for all currencies.

**Solution Options**:
1. Use v2 API endpoint (`/v2/fiatrates/{currency}`) which includes rates
2. Find alternative API that provides rates
3. Implement rate calculation on backend
4. Use separate rate provider service

## 🔄 Alternative: Direct API Calls

**Not Recommended**, but if needed:

```typescript
// Frontend would need to:
import axios from 'axios';

const response = await axios.get(
  'https://aws-dev.abcpay.cash/bws/api/v3/fiatrates/',
  {
    headers: {
      // Any API keys would be exposed here! ⚠️
    }
  }
);
```

**Problems**:
- ❌ Exposes API keys in frontend code
- ❌ CORS issues with external domain
- ❌ No caching strategy
- ❌ Frontend handles API changes
- ❌ Rate limiting hits frontend users
- ❌ No centralized error handling
- ❌ Harder to test and mock

---

## 📌 Summary

The frontend uses **GraphQL as an abstraction layer** to call external APIs through the backend. This is a **best practice architecture** that provides security, maintainability, and better developer experience.

The backend acts as a **proxy/gateway**, handling all external API communications while exposing a clean, type-safe GraphQL interface to the frontend.
